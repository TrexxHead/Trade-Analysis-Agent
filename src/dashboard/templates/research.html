How Kora decides what works

{% if store.ran_at %}Last run · {{ store.source or '' }}{% else %}Not run yet{% endif %}
Every strategy in the library ({{ n_presets }} documented methods) plus your own saved strategies is tested on your instruments with rules that stop luck from looking like skill:
  1. Chronological split. Settings, variant and timeframe are picked on the first {{ (method.IS_FRAC * 100)|int }}% of history. The last {{ ((1 - method.IS_FRAC) * 100)|int }}% is never seen until the final test.
  2. Costs. Every trade pays the spread. Boom/Crash stops hit by a spike get extra slippage.
  3. Enough trades. At least {{ method.MIN_IS }} in-sample and {{ method.MIN_OOS }} out-of-sample.
  4. Luck haircut. Testing many strategies makes some look good by chance, so confidence is adjusted for how many were tried (Sidak correction on a bootstrap p-value).
  5. Families. Related strategies (e.g. all trend followers) are also tested as one portfolio. Every member counts, winners and losers, so nothing is cherry-picked.
  6. Promotion at {{ (method.PROMOTE_AT * 100)|int }}%. Only then does a strategy feed Kora's live plans{% if not live %} (switched off in Settings){% endif %}. Everything is re-tested every week on fresh data and dropped if it stops passing.
